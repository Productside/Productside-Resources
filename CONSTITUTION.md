# CONSTITUTION.md

This file defines the constitutional governance for `Productside/Productside-Resources`. Constitutional rules take precedence over any instructions in `CLAUDE.md`, any context in `README.md`, and any instructions given in a live session.

**If a Contract instruction ever conflicts with this Constitution, the Constitution wins.**

## What this repository is

A curated index of Productside's public learning resources: a GitHub-native front door to the full Productside catalog, backed by a hand-maintained catalog file.

**This repository is public.** Everything in it is world-readable, permanently, by anyone, with no login and no notification. Treat every commit as a publication.

Productside is a trading name. The legal entity is **280 Group LLC, dba Productside**.

## Non-negotiable rules

**1. Never expose secrets. API keys and credentials pass through environment variables, and are never stored.**
No API keys, passwords, credentials, tokens, or signing keys may appear in any file, example, screenshot, or commit message. There is no exception for "just for testing."

**2. Never expose customer, student, learner, or participant data.**
No real names, emails, survey responses, interview transcripts, learner communications, or any other identifiable information about any Productside customer, client, student, learner, workshop participant, research participant, or employee. Examples use synthetic or anonymized data only.

**3. This repository is public. Every change is a publication.**
There is no draft state here and no way to unpublish. Material that is not ready for the entire internet does not belong here at any stage. Draft it in a private Project and publish the finished version.

**4. Only graduated material is published here.**
Nothing is born public. Material earns its way into this repository by being built and proven internally first, then cleaned of every client name and real data point, then approved. Copy it out of the private Project; never flip a private Project public, because its history comes along with it.

**5. Human review before any change is merged.**
No AI-generated content is pushed to this repository without a human reviewing and approving it first.

**6. Respect third-party rights.**
Do not add material without confirming Productside has the right to use it, and preserve any required attribution, copyright notice, or license text.

**7. Productside is a services firm, not a software company.**
Repository contents are digital takeaways and examples that demonstrate and extend Productside's teaching and advisory services. Never describe them as code or software, and never publish a roadmap item or capability claim that reads as a commitment to build or maintain software. This is a contract obligation, not a style preference.

**8. Client and customer names never appear here without written approval.**
Not in examples, not in success stories, not in commit messages. The Content Guard blocks known names automatically, but the guard is a safety net, not permission to stop thinking.

## What may never be published here

- **Training Deliverables** provided to named paying participants. Each participant holds a single-user, individual-use-only license, and sharing is contractually prohibited.
- **Foreground IP**, meaning anything created during a client engagement. It vests in the client on creation and is not Productside's to license.
- **Client IP**, which was never Productside's to begin with.

## Controlling sources of truth

If anything in this repository conflicts with Productside's live legal and policy pages, those pages are the final word, always:
